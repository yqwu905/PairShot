# PairShot · Android 手机多焦距与相机联动拍摄

[![Android CI/CD](https://github.com/yqwu905/PairShot/actions/workflows/android.yml/badge.svg)](https://github.com/yqwu905/PairShot/actions/workflows/android.yml)
[下载自动构建的 APK](https://github.com/yqwu905/PairShot/releases) · [CI/CD 与签名配置](docs/ci-cd.md)

PairShot 是一个原生 Android 应用：可以在“仅手机”模式使用手机镜头和变焦拍摄、导出照片 ZIP；也可以通过 USB / OTG 数据线连接相机，使用 Camera2 拍摄手机照片，通过 PTP 控制/检测实体相机拍摄，复制本次配对的相机原片，最后导出一个 ZIP。

**当前版本 0.3.0，属于待实机验证的开发测试版。联动模式优先适配尼康，已有精确型号的扩展快门适配为 Z6 第一代。没有物理手机和相机接入本开发环境，不能将软件测试通过视为硬件兼容性确认。**

## 0.3.0 仅手机多焦距模式

- 新增“仅手机”模式：只需手机摄像头权限，镜头就绪后可直接拍照，不需要外接相机、USB 授权、存储卡基线或开启联动。
- 可切换系统开放的手机镜头，并使用所选逻辑相机声明的变焦范围；提供滑条和范围内的 0.5× / 1× / 2× / 3× / 5× 快捷按钮。Android 11+ 优先使用 Camera2 变焦倍率，Android 10 使用传感器中心裁切。物理镜头输出保留原生视角；不会为不支持的设备虚构超广角或光学变焦。
- 每次拍摄独立归组，保存镜头标称物理焦距和请求变焦倍率。可换镜头或倍率后继续拍摄；支持硬件允许的双镜头组合，不自动轮拍所有焦距，也不保证双摄同时曝光。
- 手机照片齐全即可完整打包 ZIP，保留历史和重启恢复；混合批次中的联动记录仍需相机原片齐全。USB Host 改为可选，仅相机联动需要 OTG。

## 0.2.1 连接修复

修复 USB 授权回调没有携带设备信息时不继续连接的问题；授权窗口返回后也会重新核对系统权限。设备卡片直接显示授权和 PTP 连接状态及错误，避免只闪烁按钮。

连接或开启联动遇到遗留/失效会话时，最多关闭并重建一次后重读基线；不会自动重发快门。正常退出会先结束相机会话再释放 USB。失败时可展开“查看连接日志”并点击“复制诊断日志”，日志包含失败指令、返回码、事务号及应用版本，不包含照片或相机序列号。

## 对应需求与边界

| 需求 | 当前实现 |
| --- | --- |
| 不连接相机的手机多焦距拍摄 | “仅手机”模式直接拍摄所选手机镜头，按硬件能力调节变焦；手机照片齐全即可归档，不要求相机原片 |
| 使用不同手机摄像头 | 列出 Camera2 对第三方应用开放的前置、后置、逻辑相机及物理镜头；实时预览、切换镜头并拍摄 JPEG |
| 手机多摄同时拍摄 | 最多选择两枚镜头。支持同一逻辑相机下的物理双摄输出；Android 11+ 也会检查 `concurrentCameraIds` 后尝试并发相机。只有实际成功建立会话的组合才显示就绪，双摄不保证同时曝光 |
| 手机触发相机 | 手机按钮并行提交 Camera2 与 PTP 拍摄请求；Z6 使用尼康存储卡快门协议，其他机型仅在声明支持标准 `InitiateCapture` 时使用标准快门 |
| 相机触发手机 | **照片生成后的延迟跟拍**：尼康声明支持时使用 `GetEvent` 查询 `ObjectAdded`，并每 1.5 秒用新文件扫描补漏。无尼康事件能力时使用文件扫描。当前没有实现“相机物理快门按下瞬间”的通知 |
| 复制相机同步原片 | 开启联动前记录存储卡对象基线；只记录此后配对成功的照片，NEF + JPEG 同名文件归入一组；手动批量导入，可重试失败文件 |
| 同组打包 | 按拍摄记录 ID 分组，ZIP 内包含手机 JPEG、相机原文件和 JSON 配对清单；大小与 SHA-256 校验，不改变或删除相机原片 |

### 同步的真实含义

普通 USB PTP 的 `ObjectAdded` 是文件产生后的事件，`CaptureComplete` 是拍摄完成事件，二者都不是曝光前的快门按钮事件。应用明确显示这一限制，不将其当作精确同步。

- 手机带动相机：软件并行触发，USB、对焦、快门、相机处理都会造成曝光差。当前不做硬件触发、曝光锁相、相机时间校准或毫秒精度承诺。
- 相机带动手机：相机先曝光并生成文件，手机再拍摄。长曝光、NEF 写卡和扫描回退都会增加延迟；事件轮询间隔约 180 ms，扫描间隔约 1.5 s，这些是查询间隔，不是端到端同步精度。
- 若必须在相机快门按下时立即拍摄手机，需要在明确相机型号、固件和可用接口后增加并验证厂商适配，或设计外部硬件触发链路。
- 相机本地连拍可能比手机处理更快。来不及跟拍的组会标为缺少手机照片，不会悄悄归为成功。
- 手机触发模式一次仅允许一组待配对拍摄。没有可用的相机事务号时，按“唯一待拍记录 + 第一组新照片”关联；请勿同时在相机上独立拍摄。不能用未经校准的相机时钟证明同时曝光。

## 构建与安装

- Android 10 / API 29 或以上；仅相机联动需要 USB Host / OTG。
- JDK 21、Gradle 8.13（包含 Wrapper）。
- Android SDK Platform 36，Build Tools 36.0.0。
- Android Gradle Plugin 8.13.2、Kotlin 2.2.21、Jetpack Compose。

在 Android Studio 中打开 `PairShot`，安装 SDK 后构建；或设置 `JAVA_HOME` 与 `ANDROID_HOME` 后运行：

```bash
./gradlew --no-daemon --max-workers=4 assembleDebug testDebugUnitTest lintDebug
```

构建结果：`app/build/outputs/apk/debug/app-debug.apk`，应用包名 `com.pairshot.app`。APK 使用调试签名，供开发和实机验收；对外发布前应配置自己的发行签名。

本云环境的工具链已经准备，可执行：

```bash
source /workspace/.pairshot-environment/env.sh
./gradlew --offline --no-daemon --max-workers=4 \
  -ProbolectricDependencyDir=/workspace/PairShot/work/robolectric \
  assembleDebug testDebugUnitTest lintDebug
```

`robolectricDependencyDir` 是只读/离线环境的可选测试配置，目录中需要相应 `android-all-instrumented` JAR。普通本地开发不用设置它。`work/` 是开发中间文件，不随源码交付。

## 仅手机模式使用

1. 安装 APK，选择顶部“仅手机”，授权手机摄像头；不需要连接任何 USB 设备。
2. 选择系统开放的镜头。若要更换单镜头，先取消当前镜头再选择另一枚。双镜头只有系统声明支持且实际建立会话成功时可用；不支持时请使用单镜头。
3. 镜头支持变焦时，用画面底部的快捷按钮选择倍率，或点击画面右上角的倍率展开滑条。确认预览后点击紧邻画面的“手机拍照”。镜头列表可横向滑动；横屏时快门位于画面右侧。
4. 点击“打包手机照片 ZIP”，在系统文件选择器中保存。手机模式完整记录无需勾选“允许导出不完整记录”；拍摄失败或丢失镜头照片仍会标记为不完整。
5. 可通过“新建记录”另起批次，通过“历史记录”重新打开旧批次。仅手机与联动照片可以在同一批次中按不同 `mode` 保存；联动记录的相机导入要求仍然生效。

界面 mm 是 Camera2 声明的镜头标称物理焦距，不是 35mm 等效焦距，也不是当次曝光测得的实际焦距；逻辑相机变焦可能使用数字裁切或切换物理镜头。倍率是请求值，不能视为纯光学变焦。系统未向第三方应用开放的超广角、长焦等镜头无法绕过限制调用。

## USB 相机联动使用

1. 在支持 OTG 的 Android 手机上安装 APK，打开应用并授权手机摄像头。应用无网络权限、不需要账号、不需要后端，也不申请全盘存储权限。
2. 选择一枚手机镜头。系统未开放给第三方应用的镜头无法使用。如果选择双摄后初始化失败，取消其中一枚镜头再试。
3. 开启尼康相机，切换到照片模式，插入可写存储卡，使用数据线连接手机。点击“连接并授权”，接受系统 USB 授权。
4. Z6 拍摄使用当前焦点，请先在相机端完成对焦。若相机 USB 模式可选，设置为 PTP / PC 连接；关闭其他可能占用 USB 的应用。
5. 选择“手机 → 相机”或“相机 → 手机”，点击“开启联动”。建立旧照片基线期间不要拍摄。开启后，两种模式分别使用手机“同步拍照”按钮，或在相机上按快门。
6. 等待配对完成再拍下一组。手机触发模式等待相机文件的超时为 45 秒，不适合超长曝光。RAW/JPEG 生成后静默 3 秒可开始下一组；较晚到达的同组文件在监听仍开启时仍会追加。
7. 点击“复制本次相机原片到手机”或“导入原片并打包 ZIP”。导入会停止联动；请保持相机连接并避免在相机上继续拍摄，直到导入结束。
8. ZIP 准备完成后，使用 Android 系统文件选择器选择保存位置。已有原片全部导入时，即使相机断开也可再次导出。
9. 有缺失、失败或未导入原片时，默认阻止完整导出。可勾选“允许导出不完整记录”，导出已保存文件及明确列出缺失的清单。文件损坏或校验失败会阻止导出。
10. “新建记录”开始新的拍摄批次；以前的记录可通过“历史记录”重新打开。卸载或清除应用数据会移除应用内尚未导出的照片，请先保存 ZIP。

拍摄与监听仅在应用前台运行，切到后台或锁屏会停止联动。回到应用后需重新开启。拔线会立即释放 USB；已保存手机照片与已导入原片保留，未完成组显示缺失。

## ZIP 格式与恢复

```text
manifest.json
README.txt
phone/<shot-id>/<lens-key>.jpg
camera/<shot-id>/<object-handle>_<original-filename>
```

清单记录镜头、模式、触发墙钟时间、Android 单调时钟、手机图像时间戳、相机文件元数据、PTP 事务号、SHA-256、导入错误与完整性状态。`mode = PHONE_ONLY` 的记录不期待相机文件，ZIP 可只包含手机照片和清单；每张新手机照片还记录 `nominalFocalLengthMm`（标称物理焦距，已知时）和 `requestedZoomRatio`（请求倍率）。旧版记录缺少这两个字段时仍可读取。

手机图像时间戳只有在 `timestampSource = REALTIME` 时才与 `elapsedRealtimeNanos` 可比较；`UNKNOWN` 不可跨时钟相减。没有相机曝光时间戳，相机 `captureDate` 为未经校准的相机本地时间。清单中的触发时间也不能当作曝光同步误差。

拍摄记录使用 `AtomicFile` 保存，进程重启后恢复；未完成拍摄会标为不完整。照片先写 `.part` 再改名，单个文件导入失败不撤销已完成文件。重试会验证已有文件的大小与摘要。

重连后仅在相机身份摘要一致、且能可靠识别相机时，才允许继续使用旧句柄；还会重新读取并比较文件名、大小、存储位置与拍摄日期。摘要由厂商、型号和序列号生成，不保存或展示明文序列号。相机未提供序列号时，仅允许在原连接中导入尚未复制的照片，防止句柄跨设备误用。

当前不提供自动清理或删除批次的界面；应用私有目录用于持久保存拍摄记录。可先导出所有所需内容，再使用系统清除应用数据释放空间。

## 尼康协议适配

按设备能力查询选择路径，不将 Z6 扩展自动套用到 Z6 II / III、Z8 / Z9 或 D 系列。

- Z6：厂商扩展 ID 为 Nikon `0x0000000a`，型号归一化后精确为 `Z6`，且声明 `0x9207` 时启用存储卡拍摄。
- 如果声明支持，拍摄前使用 `0x90c2(1)` 进入控制模式，`0x90c8` 检查就绪。
- `0x9207(0xffffffff, 0)` 使用当前焦点并保存到卡。
- 相机忙、失焦或拒绝拍摄时不自动重发快门，防止重复曝光。
- 切换到相机主导模式或正常断开时恢复 `0x90c2(0)`，避免持续占用相机本地控制。
- Nikon `0x90c7` 在设备声明支持时查询事件，解析 16 位事件数量和每项的 16 位代码 / 32 位参数。当前未实现 `GetEventEx`、SDRAM 传输或 USB 实时取景。
- 通用文件操作使用 `GetObjectHandles / GetObjectInfo / GetObject`。图像数据阶段流式读取，超过 16 MB 的 NEF 不受小型控制容器的内存上限限制。

独立实现参考公开协议事实，未将 libgphoto2 代码打包进应用：

- https://github.com/gphoto/libgphoto2/blob/master/camlibs/ptp2/ptp.h
- https://github.com/gphoto/libgphoto2/blob/master/camlibs/ptp2/ptp.c
- https://github.com/gphoto/libgphoto2/blob/master/camlibs/ptp2/library.c

## 代码与检查

- `ptp/`：PTP 容器、数据集、尼康事件、会话、流式读取器。
- `usb/`：Android USB Host 授权后的端点传输与释放。
- `phone/`：Camera2 镜头枚举、预览、物理双摄 / 声明并发组合、JPEG 拍摄与时间记录。
- `data/`：原子拍摄记录、恢复、路径校验、摘要、ZIP 打包。
- `CameraViewModel.kt`：USB 生命周期、基线、联动、防反馈、配对、导入、历史记录和导出。
- `MainActivity.kt`：中文 Compose 工作台、运行时权限、前台生命周期、系统 ZIP 保存。

自动化检查覆盖 PTP 边界、Z6 指令路由、事件解析、RAW/JPEG 元数据、大文件分包传输、错误事务、记录恢复、导出完整性、无相机界面状态，以及仅手机拍摄/倍率/失败/防重复触发/历史恢复和 Android 10 裁切范围。测试报告位于 `app/build/reports/tests/testDebugUnitTest/`，Lint 报告位于 `app/build/reports/lint-results-debug.html`。

真机验收应覆盖：仅手机模式无 USB 拍摄、各镜头和倍率的预览/成片一致性、双摄组合、授权允许/拒绝、两种联动方式、RAW+JPEG、相机忙/失焦、拔线、进后台、进程重启、重连导入、空间不足、保存 ZIP 后解压核对。自动化测试不替代这些硬件检查。
